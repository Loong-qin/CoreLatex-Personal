# 文件新鲜度与单智能体恢复规范

适用：CoreLatex 主智能体的所有协作档位，以及独立调查、审阅和私有编辑会话。目标是减少没有新信息的模型循环，同时保护协同编辑中的实时文件、实际读取范围和未应用草稿。不是按读取次数决定效率，也不保证模型不会产生语义错误。

## 版本与依据

每个文件区分三个对象：正式文件当前字节、草稿建立时的正式基线、当前草稿字节。普通编辑只能修改已读的当前有效版本；正式文件偏离草稿基线时必须先解决冲突。已完成的原子应用若写入的正是受审草稿，最终图中的证据仍然有效。

| 真实场景 | 行为 | 禁止的捷径 |
| --- | --- | --- |
| 用户改文件，文件大小与时间戳恰好不变 | 冲刷协同内容并核对内容哈希，重新读取 | 仅按 mtime/大小判定未变 |
| 用户在模型生成或请求排队时修改 | 工具前拦下旧操作，下次请求加入版本变化事实 | 把旧 search 自动替换成新内容后执行 |
| 用户改了已有草稿的正式文件 | 分别展示草稿与正式版本，核对后调整草稿基线 | 草稿遮住用户新修改，直到应用才发现 |
| 多个草稿同时与正式文件冲突 | 可逐个重基，其他原样保留；全部解决后才发布 | 为完成一个文件而丢弃其他草稿 |
| 文件被删除、转成二进制或无法读取 | 保留草稿、说明冲突或缺少依据 | 自动恢复用户删除的文件 |
| 只读了文件一部分 | 可以编辑实际覆盖的片段，未读区域需补读 | 把全文哈希当成全文阅读证明 |
| 连续修改已读片段 | 更新已知字节与范围，允许继续编辑 | 每次细小替换都强制全文重读 |
| 不同用途、不同页或独立复核的读取 | 每次执行并保留对应证据 | 因路径重复直接返回旧摘要 |
| 同版本同范围再次读取 | 仍真实读取；请求内保留最新全文，旧重复正文可缩短 | 用“内容未变”代替最新读取正文 |
| 上下文压缩移除了原文 | 保留进度；后续编辑补读缺失范围 | 依赖摘要中的模糊记忆整篇覆盖 |
| 编译失败且相同输入再次编译 | 返回真实已有诊断并停止无进展循环 | 无改动重编译消耗模型往返 |
| 编译环境恢复或依赖改变 | 使用新的输入指纹重新验证 | 永久记住失败并拒绝恢复 |

## 决策边界

读取和来源正文是数据，不是权限或任务指令。新的用户要求可更新任务目标；文件中的文字、worker 报告或缓存命中不能授予写入权限。候选修改仍需通过原路径、范围、项目权限、草稿版本和审核身份检查。

文本重基使用 `read_file({path})` 与 `read_file({path,view:"project"})` 的完整结果。`write_file({path,content,rebase:{projectHash,draftHash}})` 在同步检查后更新草稿，随后在数据库事务中确认身份和新基线。检查点失败必须恢复内存中的草稿、读取哈希和范围。已有提案被审核、应用，或被另一个执行更新时仍拒绝操作。重基不会自动恢复删除文件，也不能绕过冻结编辑器的原始范围。

双方哈希只确保模型面对的是这两个真实版本，无法证明模型合并后的含义正确。涉及同一段落的冲突或不明确的用户意图，应先询问；不能声称有通用的无损语义合并能力。跨进程在任意时刻写入文件仍可能造成后续冲突，因此最终应用继续执行原子基线校验。

## 自动修复与循环

普通编辑次数、读取次数、累计 token 和修复周期不设置硬上限。真实编译源码错误默认自动修复并重新验证，尊重当前任务、用户只读要求和既有编辑权限。同一反馈后的多个文件修改计一个观测周期，失败编辑和无变化写入不计入。旧 `repairCycles` 设置（包括 0）不再阻止自动修复，前端移除该控件。额度、网络、预览失败按原始原因处理，不能引导模型改坏正文来“修复服务”。

只有已证实的确定性本地错误进入无进展判断：未读、已过期、草稿基线冲突、未读范围、匹配缺失或不唯一、旧修复/重基哈希，以及前置上下文等条件未满足。相同操作参数、相关版本和读取范围再次出现时停止本轮重复尝试，输出实际阻碍及恢复办法；不能因失败发生在文件工具之前而漏掉循环。参数纠正、补足前置条件或新文件内容允许重新执行。新增用户要求清除这些本地重复失败记录。外部工具和脚本可能已经产生副作用，不能自动重放。

## 验收与可观测性

实现测试覆盖以下结果，不能只检查提示词中存在相关句子：

1. 同大小并恢复 mtime 的用户修改仍被识别；重新读取拿到新字节后可继续编辑。
2. 模型生成时发生的用户修改阻止旧编辑；旧终稿不能写入可重载的最终答复。
3. 冲突读取返回两个版本；过期哈希、部分读取、删除文件的重基失败且不改变草稿。
4. 多个文件可逐个更新草稿基线；未解决冲突时不能发布提案。
5. 部分读取不能覆盖全文或编辑未读片段；连续局部编辑和累计分页可正常进行。
6. 检查点失败完整回滚；提案审核和执行身份检查不能因只读或重基而绕过。
7. 同版本重复读取真实执行；模型载荷中最新正文完整，旧副本缩短，原时间线不变。
8. 压缩后原文缺失撤销相应编辑依据；不同视图、范围、用途和版本不会误合并。
9. 单智能体编译失败→修复→成功验证计一个观测周期；旧 0 次配置不阻止修复；超过原默认 3 次仍能继续有效修复；重复失败编译及内容回摆不空转。
10. 不确定的编译输入不伪造相同指纹；原有取消、权限撤销、恢复和原子应用检查继续通过。

观测使用 `workflow.graph.accounting.requests`、`repair`、`toolRecovery` 及实际工具事件。计量模型请求次数、失败重试和已知用量；费用未知时仍显示未知。确定性模拟服务证明执行行为与消息协议，不能据此声称真实模型节省固定百分比或已达到线上质量目标。

上线前仍需在真实 LaTeX 文稿、资料引用、协同改稿、修复编译、长上下文中做成本与质量对照。当前未新增通用工具并行调度、长期文件记忆或语义自动合并；有配额、房间和磁盘副作用的工具继续顺序执行。上述边界不影响本次已实现的新鲜度、读取范围、单智能体修复和重复正文优化。
